# 墨锭试磨室

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`。

## 环境巡检

受潮墨锭继续试磨会把裂纹盖住，因此环境巡检已接入建档与试磨流程。

- **建档即巡检**：新增墨锭时同时登记入库巡检单，记录库位、温度、湿度、外观和巡检人；
  外观见霉点或软边即自动隔离（状态置为「已隔离」），禁止试磨。
- **试磨闸门**：只有当前有效巡检单结论为「正常」时才允许创建试磨记录；
  待复验、已失效或未巡检一律拒绝。
- **复验恢复**：复验须换人（不能由初检人执行，相邻两次也不能同人），
  间隔满 12 小时做两次，两次湿度均低于 65% 且外观正常才恢复试磨。
  不合格的复验留痕但不计入合格序列。
- **结论失效**：改库位或更正巡检值会让原结论失效，旧单标记「已失效」但仍保留可查；
  每锭只保留一张未失效（正常/待复验）巡检单，新单自动顶替旧单。

巡检单列表可按「正常 / 待复验 / 已失效」筛选。

## 文件结构

- `inspection.js` —— 判定：纯业务规则（缺陷识别、复验换人/间隔/次数、结论三态），无 IO。
- `storage.js` —— 存储：JSON 持久化与巡检单不变量（每锭一张未失效单、失效留痕）。
- `page.js` —— 页面：建档/试磨/巡检/复验的交互界面与三态筛选。
- `server.js` —— 路由：建档、移库、试磨闸门、巡检与复验接口。
